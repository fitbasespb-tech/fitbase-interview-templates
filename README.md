# Fitbase — шаблоны интервью

Набор HTML-шаблонов для проведения интервью с клиентами и партнёрами Fitbase. Открываются в браузере, работают офлайн, ничего не отправляют наружу. Заметки и чекбоксы сохраняются в `localStorage`.

## Что внутри

| Шаблон | Назначение | Аудитория |
|--------|------------|-----------|
| [levita_switch_interview.html](levita_switch_interview.html) | Внутреннее исследование: Switch-интервью по 4 силам Замесина — Левита → Listok+АМО → Fitbase | Бывшие франчайзи Левиты |
| [case_subscription_studio.html](case_subscription_studio.html) | Публикуемый кейс: переход студии (пилатес/йога/танцы) с классических абонементов на подписочную модель | Студии S1 |
| [case_volk_crossfit.html](case_volk_crossfit.html) | Публикуемый кейс: переход кроссфит-клуба с системы блоков (4/8/12/16) на GREY/WHITE подписку | VOLK™ CrossFit и подобные форматы |

## Структура файлов

Каждый шаблон — самодостаточный HTML-файл со встроенным CSS и JS. Открывается двойным кликом.

### Что есть в каждом шаблоне

- **Sticky-таймер** — старт/пауза/сброс. Меняет цвет на 30+ мин (оранжевый) и 38+ мин (красный)
- **Навигация по секциям** в шапке — клик переносит к нужному блоку, посещённые подсвечиваются
- **Поля для заметок** после каждой секции — сохраняются в localStorage
- **Чекбоксы** на установке и закрытии — для контроля разрешений и материалов
- **Цветовая маркировка вопросов**:
  - ★ Ключевой вопрос (жёлтый) — открывает суть боли/решения
  - 🔊 Цитата для кейса (розовый) — дословная, для прямого включения в статью
  - 📊 Цифры для кейса (зелёный) — конкретные «было/стало», для графики
- **Кнопка экспорта в Markdown** — генерирует файл со всеми заметками, разбитыми по секциям
- **Кнопка печати** — для бумажной копии
- **Адаптация под мобильный** — можно открыть с телефона
- **Print-стиль** — при печати убираются таймер и навигация, остаются вопросы и места под заметки

## Как использовать

### Перед интервью

1. Открой нужный шаблон в браузере: `file:///путь/к/файлу.html`
2. Прокликай навигацию — освежи структуру
3. Если что-то остаётся от прошлого интервью — нажми «Очистить» внизу страницы

### Во время интервью

1. Нажми **Старт** на таймере
2. Иди по секциям. Заметки пиши в текстовые поля под каждой секцией
3. Помечай в чекбоксах что подтверждено (разрешения, контакты)
4. Если уходишь по таймингу — смотри блок «Если идёт "не туда" — минимум на 20 минут» в конце страницы

### После интервью

1. Нажми **📋 Экспорт заметок в Markdown** — скачается файл со всеми заметками
2. Доработай в статью или положи в `Knowledge/Interviews/<Сегмент>/<Имя>_Analysis.md` по [каноническому шаблону AJTBD](https://github.com/fitbasespb-tech/fitbase-jtbd-master)
3. Если нужно — запроси материалы (фото, скриншоты дашборда) по чек-листу в конце

## Методология

### Switch-интервью (Замесин)

Используется в `levita_switch_interview.html`. Идея: пользователь совершил переход — нужно понять **4 силы**, которые на него действовали:

- 🔴 **PUSH** — что выталкивало из старого состояния
- 🟢 **PULL** — что притягивало к новому
- 🟡 **ANXIETY** — что пугало при смене
- 🔵 **INERTIA** — что почти удержало

### Кейс-интервью

Используется в `case_*.html`. Структура для публикуемого материала:

1. **ДО** — что было, что болело, цифры старой модели
2. **РЕШЕНИЕ** — что подтолкнуло, сомнения, момент решения
3. **КАК** — пошаговая механика перехода
4. **ПОСЛЕ** — измеримые результаты, что изменилось
5. **СОВЕТ** — рекомендации другим, кому подходит / не подходит

### Канонический шаблон разбора

После интервью разбор кладётся в `Knowledge/Interviews/<Сегмент>/` по канону из репозитория [fitbase-jtbd-master](https://github.com/fitbasespb-tech/fitbase-jtbd-master) — 10 секций (бизнес+ЛПР → Situations → Big/Core/Middle/Small → Switch → критерии → хуки → цитаты → продукт → сегмент → ссылки).

## Создание новых шаблонов

Если нужен шаблон под другой сегмент — клонируй любой `case_*.html` и адаптируй:

1. Замени заголовок и подзаголовок в `<title>` и `.title-row`
2. Обнови содержимое блоков `before`, `decision`, `process`, `after`, `advice` под специфику сегмента
3. Адаптируй чек-листы материалов и разрешений
4. Поменяй ключи в `data-key` атрибутах textarea, чтобы заметки не путались с другими шаблонами (например, `'note_volk_'` → `'note_<твоё_имя>_'`)
5. Обнови генерацию имени файла в `exportNotes()`
